## Ownership and behavior

`MetricsProvider` now consumes the `MetricsReading` port. `HostMetricsReader` owns Mach, filesystem and process access; the provider owns counter baselines and sampling policy. Shared Foundation-only `ReadingStatus` distinguishes available, waiting and failed CPU, memory, network and disk readings. Process-list failure and unknown thermal pressure remain explicit. A failed memory or disk read no longer becomes a normal zero percentage/capacity in compact labels, panels or diagnostics.

Network rate calculations use monotonic elapsed time and bounded numeric conversion. Failed/decreasing counters and changed interface sets establish a new baseline. Hiding System while Disk keeps the provider active also clears CPU/network baselines, preventing stale counters from producing a transfer spike on re-enable. Interface names arrive in the same sampled data; presentation no longer calls `getifaddrs`. Disk capacity and process output validate before numeric conversion, including nonfinite values and partial command output.

Each history series skips failed/warm-up readings and keeps matching timestamps. `metricsSampledAt` makes another provider's publication of cached metrics distinct from a new measurement, preventing duplicate history points. Compact sparklines suppress current unavailable readings; detail graphs retain valid history. Simple inspectors wrap status messages and reserve each row's required height before attachment.

`AudioProvider` consumes `CoreAudioAccessing`. `CoreAudioAccess` owns raw buffers, response bounds, CFObject ownership and OSStatus checks. Failed inventory, failed default-device reads, successful empty lists and partial property failures stay distinct. Unreadable volume/mute remain unknown; their controls are disabled, an unknown volume slider is hidden, and mute accessibility state is mixed. Readable device information survives partial failures. Commands re-read the device and capability before writes, reject nonfinite volume, and identify a partial stereo write rather than claiming no change. Master and mono/stereo software controls are supported; multichannel devices without a master use hardware controls.

Audio and empty/unavailable VPN panels expose Retry and direct system-settings actions. Retry asks `WidgetRuntime` to sample only that provider, coalesces in-flight work and rejects hidden widgets. The controller avoids a duplicate general refresh. Native tests verify dispatch and scroll reachability without opening personal system-settings panes; the runtime test verifies a real second read through the injected adapter.
