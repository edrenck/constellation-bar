## Ownership and corrected behavior

`ConfigurationRepository` now owns Foundation-only loading/error state, destination protection, backup and atomic persistence. Active/writable path resolvers are injected, allowing separate instances over temporary files. The existing `ConfigurationStore` facade keeps canonical application path selection, notifications and alerts. `ConfigurationEditingSession` retains its transaction boundary and injected persistence operation.

A missing default source clears a previous load error. Retry Save re-reads a failed source before deciding whether the operation remains blocked: moving or repairing a malformed default file no longer requires an app restart or an extra Reload. Existing malformed destinations remain protected, repaired valid files are backed up, explicit exports do not erase an active-source error, and explicit unreadable paths remain errors. Regression tests preserve original malformed bytes and verify instance error isolation.

`PanelFocus` captures the focused body control's stable ID and optional UTF-16 text-selection range before a structural rebuild. It restores the corresponding enabled control, clamps a restored selection to the current text, and reveals that control after layout. A removed control gets a nearby usable fallback or Close. It does not activate windows or move header focus into the body. Shared helpers assign IDs, with feature IDs for changing labels and potentially duplicate names: Timer's primary action, media transport, Audio device/mute controls, Calendar events/dates/sources, keyboard sources and VPN expansion/search/actions.

Native window journeys verify Pause → pending → Resume focus, VPN search text/selection through a structural update, fallback when a Calendar event disappears, and unchanged Close focus during a body refresh. These are AppKit first-responder/selection assertions; they do not establish full hardware-keyboard or VoiceOver behavior.

`ApplicationMenu` is the menu builder installed by `AppDelegate`. It supplies standard Edit commands with responder-chain targets. Local key-equivalent tests use native events, a native text editor for Select All, and isolated command receivers for Undo/Redo/Cut/Copy/Paste. The Redo equivalent uses uppercase `Z`; its event-dispatch check distinguishes it from Undo. The test receivers leave the personal pasteboard unchanged. [Apple's menu-key-equivalent documentation](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/MenuList/Articles/SettingMenuKeyEquiv.html) describes the character/modifier contract.

Calendar details now use `AgendaEvent.scheduleDescription`: single all-day events show “All day”; multi-day all-day events add a date span; timed events crossing midnight include dates and times. The formatter handles both modern macOS's last-day 23:59:59 representation and legacy exclusive-midnight endings, including a span across daylight saving. [Apple TN3130](https://developer.apple.com/documentation/technotes/tn3130-changes-to-eventkit-in-macos13-ventura) documents that platform difference. Events and account data remain read-only.

Four fresh fixtures cover single/multi-day/overnight Calendar details and the Timer focus ring. The constrained Weather fixture now supplies matching configured preferences and fresh sample metadata, removing its contradictory unconfigured message. These are constructed render states, not live account/weather observations.
