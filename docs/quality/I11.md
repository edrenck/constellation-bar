# I11 — Stable settings controls and visible recovery

Recorded 2026-11-05. Base revision `804b03f4a3d045eab27b3b8371f3c2b8ed05d678` plus uncommitted changes. Frozen source SHA-256 `a9ab86e97997577444ed4fd373ef7d9201474d39caa4bb9984c018f1090ecdcd`; tests SHA-256 `29102eab958e29298fc770163324d5a907657f67d7c8fea4544e3e87c308a140`.

## Reproduced gaps and resulting behavior

Four initial native methods failed against I10 with **14 assertion failures, zero unexpected failures**. Reordering replaced the focused widget controls; display controls lacked visible-label associations; metric history exposed a generic name without useful values; and the minimum settings window required horizontal panning with save recovery outside the visible sidebar. These are deterministic control/property/geometry reproductions, not actual hardware-keyboard or VoiceOver journeys.

`WidgetArrangementRow` now owns a widget's native zone/reorder/configure controls and typed callbacks. `DisplaySettingsEditor` reconciles these rows by `BarItem` identity instead of recreating controls and decoding their identifiers for each action. Reordering and zone changes retain logical control identity. A newly disabled reorder button falls back to the same widget's zone picker; hiding that widget returns focus to Add widget. Undo can restore the cached row. Deferred reveal runs only while the target remains focused. Controls for widgets with no configurable settings are removed from their hierarchy, preserving the existing contract. Display size/workspace fields now expose their visible-label associations.

`SettingsWindowLayoutView` owns wide/compact navigation constraints independently of the editing transaction. Width below 860 points or height below 560 uses a section picker and the full-width form. Short windows hide duplicate headings and the live preview, retaining selected-display scope. Resizing moves navigation focus to its visible equivalent; page changes retain navigator focus. The supported 640-point form fits all five sections, and a native test also checks every default widget-options form with long Aerospace path, workspace-name and Weather-label values. Vertical scrolling still exposes content below the first view. Narrower physical frames retain the horizontal fallback; real displays are not qualified by these synthetic sizes.

`SettingsRecoveryView` keeps save state, Undo, Retry Save, Revert and Details outside scrolling documents. A failed save leaves the desktop on the saved snapshot. Full errors remain in the status value and open through Details in a native bounded, selectable, read-only text view; long messages no longer push recovery actions offscreen. User/developer copy now locates Undo at the bottom of the window.

`MetricPlot` exposes a metric-specific name and summary of the recorded sample count, latest/minimum/maximum, units and selected window. Current measurement failure is stated separately from recorded history; empty history does not invent a zero. Invalid/nonfinite samples are excluded from both summary and drawing, and network conversion to the byte formatter is checked. Native tests inspect the accessibility element/value, including failed/empty/invalid/large network values. [AppKit's value-description API](https://developer.apple.com/documentation/appkit/nsaccessibility-c.protocol/accessibilityvaluedescription) supports a human-readable description; these assertions do not establish a complete VoiceOver chart journey or an interactive data table.

The [architecture guide](../ARCHITECTURE.md) maps the new UI responsibilities and keeps view geometry separate from `ConfigurationEditingSession` persistence and runtime/provider work.
