## Ownership and behavior

`AppDelegate` now constructs one [WidgetRuntime](../../Sources/ConstellationBar/Core/Widgets/WidgetRuntime.swift) and one [IntegrationDiagnostics](../../Sources/ConstellationBar/Core/Widgets/IntegrationDiagnostics.swift), then passes both to the bar and settings through the status controller. [WidgetServices](../../Sources/ConstellationBar/Core/Widgets/WidgetServices.swift) composes the concrete adapter inventory, with injectable timer, awake, Reminders, keyboard, calendar, audio and media dependencies plus the asynchronous Music authorization effect. There is no global `WidgetServices.shared`; `SystemMonitor`, `MediaProvider` and `CalendarProvider` require their inventories explicitly.

The runtime owns one graph and one monitor. Commands reach the same instances sampled on their provider queues. Explicit permission setup from settings can run before sampling or while the widget is hidden, without activating it. Setup still enters the corresponding provider queue; ordinary panel commands require an enabled generation. Apple Calendar and the Outlook adapter share the injected calendar store. Permission completion returns to the main queue after the actual permission result, rather than after queue dispatch. A stopped monitor rejects new setup and cancels setup still waiting behind a read. Stop is terminal for that monitor; create a new runtime to start a new lifecycle.

Diagnostics samples, workspace health and action failures are instance-owned, and their changed/refresh notifications are scoped to that instance. The canonical configuration repository publishes a separate file-status notification. A save no longer impersonates a provider-status event. Existing configuration-store/updater status and OS services are not all converted to instances by this checkpoint.

Music's [MediaPanelContent](../../Sources/ConstellationBar/Widgets/Media/MediaPanel.swift) now owns source selection, Playing/Up Next selection, the content signature and authored controls. It holds the shared panel weakly. `MiniAppPanel` retains chrome, lifecycle, sampled state and action routing. Native tests verify independent panel selections, selected-source command routing, refresh retention, removed-source fallback and host release. Other feature panels still share broader shell state; this is the first extraction, not a completed panel framework migration.

The [architecture guide](../ARCHITECTURE.md) documents the startup graph, backend responsibilities and provider registration path. No extra package target, generic service locator or inheritance framework was introduced.

## Remaining work

The [blind assessment](reviews/I4.md) rated code quality **8.5**, usability **8.0** and UI **8.0**. It confirmed the composition/testing strengths and identified low-contrast green status text in light fixtures, stale Calendar selection, actual-window sizing, remaining shared feature state and nested Compact outlines. The lower UI rating is preserved along with its newly observed evidence. No source changed after review.

Keyboard entry to the bar, actual constrained-screen window sizes, Core Audio failure semantics and expandable panel error/overflow feedback remain open. Calendar, VPN and System content still need feature ownership; Calendar filtering still persists outside JSON/Undo. Physical-display, minimum-OS/Intel, live VoiceOver/material and signed-install/update qualification remain unestablished. This checkpoint does not declare production readiness.
