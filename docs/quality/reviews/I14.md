Prioritized findings:

1. **P2 — Repeated metrics reads appear to leak Mach host-port send-right references.**  
   **Source-inferred, not runtime-measured.** Both [SystemUtilities.swift:48](/Users/edrenck/constellation-bar/Sources/ConstellationBar/Core/SystemUtilities.swift:48) and [HostMetricsReader.swift:26](/Users/edrenck/constellation-bar/Sources/ConstellationBar/Widgets/System/HostMetricsReader.swift:26) call `mach_host_self()` during recurring reads without balancing the acquired rights with `mach_port_deallocate`. No matching deallocation exists in the inspected source. For an always-running status utility, this deserves correction and a sustained resource-usage check.

2. **P1 qualification gap — Active keyboard operation remains unqualified.**  
   **Supplied execution evidence.** [keyboard-activation.log:1](/Users/edrenck/constellation-bar/.build/production-readiness/i14/keyboard-activation.log:1) reports activation timeout with `screenLocked=true`; shortcuts were explicitly not exercised. Complete an unlocked-session journey through settings, bar controls, pinned panels, scrolling, Escape, and editing shortcuts, followed by VoiceOver qualification. This is an evidence gap, not proof that keyboard support is broken.

3. **P2 — Core native behavior depends on private APIs across a broad advertised OS range.**  
   **Source-inferred compatibility risk.** Fullscreen detection calls dynamically resolved SkyLight functions in-process through `unsafeBitCast`: [FullscreenDetector.swift:36](/Users/edrenck/constellation-bar/Sources/ConstellationBar/Shell/FullscreenDetector.swift:36). Missing symbols and unknown Space types have sensible fallbacks, but those checks cannot establish ABI compatibility. MediaRemote is better isolated in a bounded subprocess: [NativeMediaIntegration.swift:20](/Users/edrenck/constellation-bar/Sources/ConstellationBar/Widgets/Media/NativeMediaIntegration.swift:20). The supplied current environment is arm64 macOS 26.6.2; it does not qualify Intel, older supported macOS versions, physical multi-display arrangements, or live materials.

4. **P2 — The always-on polling paths need energy and scaling measurements.**  
   **Source-inferred risk, not an observed slowdown.** The frame timer runs every 50 ms and captures menu visibility separately for each display; on multi-display systems that path enumerates WindowServer windows: [ScreenBarController.swift:81](/Users/edrenck/constellation-bar/Sources/ConstellationBar/Shell/ScreenBarController.swift:81), [ScreenBarController.swift:279](/Users/edrenck/constellation-bar/Sources/ConstellationBar/Shell/ScreenBarController.swift:279). System sampling launches `ps` when CPU/memory is enabled, and native media sampling launches Perl/helper processes. Measure idle CPU, wakeups, subprocess churn, and responsiveness with several displays and large event/window collections before declaring the app lightweight.

5. **P3 — Timer completion is easy to miss.**  
   **Source-confirmed product limitation.** Completion changes state and presentation, but sends no notification or sound: [TimerProvider.swift:21](/Users/edrenck/constellation-bar/Sources/ConstellationBar/Widgets/Daily/TimerProvider.swift:21), [DAILY_WIDGETS.md:5](/Users/edrenck/constellation-bar/docs/DAILY_WIDGETS.md:5). This is documented honestly, but limits the practical value of a countdown when its bar is hidden by fullscreen or the user is elsewhere. An optional completion notification would materially improve it.

6. **P3 — Music’s “Up next” tab promises more than the implementation supplies.**  
   **Source-confirmed usability issue.** The tab is always present, yet its content always explains that the provider does not expose a queue: [MediaPanel.swift:107](/Users/edrenck/constellation-bar/Sources/ConstellationBar/Widgets/Media/MediaPanel.swift:107). Hide or capability-gate it, or replace it with a direct “View queue in Music” action where available.
