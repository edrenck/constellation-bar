The app has strong engineering foundations and a coherent visual system. I found no confirmed major functional failure in the inspected fixtures. The remaining gaps concern responsive content priority, live settings reconciliation, and qualification of keyboard/accessibility behavior.

Actionable findings, in priority order:

1. **Active-application keyboard routing remains unqualified.** The supplied `keyboard-activation.log` reports exit 1 with `active=false, key=false, main=false, canKey=true`. This establishes a failed probe, not its cause or a confirmed user-facing shortcut defect. `RecoveryKeyboardTests.testMenuKeyEquivalentsSelectTextAndDispatchEditingCommands` explicitly assigns isolated targets, so its success cannot establish production responder-chain routing. Get the actual application active/key and complete `KeyboardSmokeJourney` before claiming that journey passes.

2. **Constrained layouts preserve access through scrolling, but frequently hide the panel’s main purpose.** In `constrained-nowPlaying.png`, artwork and metadata consume the initial viewport; transport controls are below it. `constrained-calendar.png` initially exposes navigation and dates but no events. Even normal `mini-app-audio.png` cuts through Retry and puts Sound settings below the viewport. Fixed preferred heights in `Shell/Panels/MiniAppPanel.swift:52` contribute to uneven density: sparse Timer/Reminders panels have substantial empty space while Audio already scrolls. Compact artwork/navigation and content-sensitive sizing would improve the first view. This is fixture-observed friction, **not inaccessible content**: `ConstrainedWindowTests` meaningfully verifies scrolling controls into view.

3. **Reminders settings bypass the adapter boundary and can retain stale list choices.** `Settings/DailyWidgetSettings.swift:25` constructs `EKEventStore` and reads lists directly. Choices rebuild at initial construction and that settings page’s successful Allow callback; ordinary synchronization only updates existing checkbox states. `ConfigurationWindowController.swift:476` refreshes launch-at-login state on reactivation, not lists. Consequently, access granted through the widget or external list changes can leave an already-created chooser stale. This is a **static inference**, not a reproduced consent journey. Consume an injected list snapshot and reconcile authorization/list identity changes, with a regression covering permission granted elsewhere.

4. **Music advertises an unsupported queue tab.** The normal fixture offers “Up next,” while `Widgets/Media/MediaPanel.swift:79–86` always replaces it with an unsupported-provider explanation and optionally an external Music button. Indicate that destination/capability before selection, or present the external queue action directly. This is a small discoverability issue, supported by fixture and source.
