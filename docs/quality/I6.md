## Failure handling and ownership

CPU sampling now accepts an injected counter reader. The Mach reader throws on failure instead of returning zero counters. `MetricsProvider` clears the baseline after a failed read and waits for a new valid pair; any decreasing component, including counter wrap, establishes a new baseline before subtraction. Deltas are summed in floating point after checking individual monotonic components, avoiding unsigned underflow and integer-total overflow. Deactivation clears the sampling baseline.

`CPUState` distinguishes available, waiting and failed readings. Compact labels, System details and diagnostics consume that state. A failed or warm-up reading is shown as unavailable/collecting rather than 0%. CPU history skips those readings and retains matching timestamps independently of other metrics. The System diagnostics entry was added after a native regression exposed its absence. Memory, disk, network and process-reader failure semantics are not generalized by this change.

VPN adapters return typed availability in `VPNReadResult`, separate from display messages. Failed, timed-out or truncated macOS listings are rejected before parsing; a successful empty listing remains distinct. Each sample replaces the adapter's prior statuses, preventing a prior success from making a failed read available. Panel messages and compact tooltips explain unavailable sources alongside any available connections.

`WidgetServices` now owns/injects the sampled `VPNProvider` for commands too. The provider rechecks a fresh, successful service listing before start/stop and reports command failures. Tests use its injected runner without changing actual VPN services.

`AgentStatusProvider.deactivate()` reaches the remote monitor's existing generation invalidation and queued-operation cancellation. A regression removes Agent Status through `SystemMonitor`, with one SSH probe running and three queued, then checks cancellation and that an old completion cannot reappear after re-enabling. An already-running command remains bounded by its existing timeout; this change does not terminate it early.

The ordinary Calendar preview now creates events and its browsing range from the panel's sample date, so its populated details are represented. New fixtures cover CPU failure/warm-up and VPN unavailable states. These fixture changes do not alter Calendar's application behavior.
