## Ownership and behavior

[CalendarPanelContent](../../Sources/ConstellationBar/Widgets/Calendar/CalendarPanel.swift) owns browsing day, calendar chooser and selected event, with a weak reference to the shared host. When events disappear or filters change, selection follows the first remaining visible event. Navigation stops at the sampled range and a Today action returns to the current day. Advancing the sampled range reconciles an obsolete browsing day. Narrow panels stack the headline/navigation and agenda/details vertically.

[CalendarSelectionStoring](../../Sources/ConstellationBar/Widgets/Calendar/CalendarSelectionStore.swift) separates the local preference repository from the view. The runtime's calendar queue processes visibility commands against the same store sampled by `CalendarProvider`. Snapshots carry hidden calendar IDs to both compact presentation and detail content; neither reads UserDefaults directly. The implementation preserves the existing local key and its account-specific, per-Mac semantics. Filters intentionally remain outside portable JSON and configuration Undo, as documented in the canonical guides.

[WindowPlacement](../../Sources/ConstellationBar/Shell/Panels/WindowPlacement.swift) limits actual overlay size and position to the available screen frame. The coordinator reapplies it on refresh. Rich panel bodies rebuild for the constrained width, with scrolling for overflow; Close and Pin remain outside the document. Shared action errors wrap inside the document and reveal their beginning, with a short footer status and full tooltip. Simple inspector rows now have a scroll document. Settings fits the screen frame and has separate scrollable sidebar/recovery and form documents. A form wider than its viewport remains horizontally scrollable.

[BarTheme.textAccent](../../Sources/ConstellationBar/DesignSystem/TextContrast.swift) resolves dynamic colors in the selected appearance and adjusts colored text against its opaque theme background. Agent status, VPN status and large System readings use that role. Tests require at least 4.5:1 across themes, following [W3C's normal-text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). This is a conservative opaque-surface criterion, not an application-wide accessibility or live-glass conformance claim.
