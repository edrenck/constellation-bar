Recorded 2026-11-05. Base revision `804b03f4a3d045eab27b3b8371f3c2b8ed05d678` plus uncommitted changes. Frozen source SHA-256 `f7244af357f6da8ea2d318949208b6be572ee7181677076bd2bf8956d2e13767`; tests SHA-256 `285bd0115735be40dbdbfd1e9886102e3dc640e192a02e8811a484673f74e0d7`.

## Reproduced problem and resulting behavior

Reminders settings previously constructed its own EventKit store and enumerated lists directly. Two native regressions failed against that implementation: granting access through the widget runtime did not update an already-created settings chooser, and app reactivation did not discover lists from the injected reader. The saved before run has **two tests, two assertion failures, zero unexpected failures**. This turns the prior static ownership concern into deterministic evidence; it does not reproduce a real OS consent journey.

`RemindersReading` now provides list-only discovery and an optional invalidation subscription alongside task reads and explicit permission requests. `RemindersProvider.listSnapshot` checks authorization before and after discovery. `ReminderListSnapshot` removes names when unauthorized. `WidgetRuntime.readReminderLists` uses `SystemMonitor.readSetup`, so discovery enters the same serial queue as sampling and actions, including while the widget is hidden or has never sampled. It reads list metadata without fetching task contents or requesting permission. A stopped runtime rejects new/queued discovery and drops results that finish after stop.

`AppleRemindersReader` observes changes from its own EventKit store and returns a cancellation operation. The runtime scopes the resulting notification to its own instance, invalidates the task cache on the provider queue, and requests a new sample only if that widget is active. Settings refreshes on permission completion from either surface, store invalidation, presentation and application reactivation. Stop cancels observation. This follows [Apple's store-change and refetch guidance](https://developer.apple.com/documentation/eventkit/updating-with-notifications); platform objects stay within the adapter.

`ReminderListSettingsView` owns discovery/loading/error presentation and list-control identity. Invalidations during a read collapse into one follow-up; the superseded value is discarded. Renames and reordering retain controls and focused identity. Automatic reconciliation updates checkbox state from the current configuration without saving. Missing selected IDs remain explicit, removable “Unavailable selected list” checkboxes, preventing a deleted or temporarily missing list from silently changing the filter to all lists. A user may uncheck them deliberately. Revocation and discovery errors remove private list names. Refresh lists retries metadata discovery; Allow access appears only when access is known to be missing, rather than treating a list-service failure as a permission failure.

`ConfigurationWindowController` supplies the runtime and routes explicit selection/authorization actions. `DailyWidgetSettings.swift` no longer imports EventKit or reads accounts. The [architecture map](../ARCHITECTURE.md) and [daily-widget guide](../DAILY_WIDGETS.md) describe these responsibilities and semantics.
