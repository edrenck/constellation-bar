## Behavior and ownership

`BarController` now maintains a one-second local presentation timer while the resolved display scope includes Timer, Keep Awake, Clock or Reminders. `WidgetRuntime.refreshLocalTime` asks only active Timer/Keep Awake providers for a sample through their existing serial queues. External providers retain their configured polling cadence; hidden/stopped generations are rejected. Clock and overdue presentation use the current wall date. Scope changes remove the local timer when its last dependent widget disappears, and stop invalidates it.

A native regression starts the actual controller with general and workspace polling both set to 60 seconds. Injected continuous clocks advance while the real run-loop timer drives remaining-time publication, countdown completion and awake-session expiry. Before the fix, the expected local update did not arrive. This exercises application scheduling beyond direct model calls. Independent monitor coverage verifies that local requests skip external and hidden providers and stop after shutdown.

Resuming an already-running Timer no longer resets its deadline from a stale remaining value. Positive fractional countdown seconds round upward consistently in compact presentation, panels and diagnostics; the last fraction shows `0:01` until completion. Media elapsed-time formatting retains its existing behavior. Deadlines still use continuous monotonic time; there are no new notifications or persistence across app exit.

`KeepAwakePanelContent` owns the inactive next-session display choice, holding a weak reference to the common panel host. Toggling an active session dispatches `keepAwakeDisplay` immediately through the sampled provider's action queue. `KeepAwakeProvider.setDisplayAwake` creates a replacement assertion before releasing the old one, preserves the original deadline and allows replacement during the final fraction of a minute. Failed creation leaves the original assertion/mode/deadline intact; an expired session cannot silently become a fresh session. A failed initial start also preserves the panel's next-session choice. The panel explains which session the checkbox affects.

`ReminderDeadline` retains the original EventKit date components, rather than converting date-only tasks to a synthetic time. Date-only labels omit time. Overdue comparison uses the next calendar-day boundary, including 23-/25-hour daylight-saving days and the final fractional second of the due day. Floating components resolve in the current context; explicit time zones stay fixed. An all-day label stays on its due day when viewed from another zone. Timed tasks retain their actual time. The panel updates overdue text when the boundary passes without requiring a new fetch. The source semantics are documented in [Apple's due-date components API](https://developer.apple.com/documentation/eventkit/ekreminder/duedatecomponents), also checked against the installed EventKit SDK header.

The EventKit reader still reads incomplete due tasks and does not write reminders or request permission during sampling. Its predicate, selected-list behavior, bounded cache and retry policy remain in the reader/provider boundary. Foundation-only deadline tests require no EventKit account access.
