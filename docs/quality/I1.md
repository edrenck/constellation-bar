## Resulting behavior

- **Weather input:** invalid, nonfinite and out-of-range coordinates remain visible with a field-specific error. They cannot persist or apply through Retry, navigation or unrelated settings edits. Correcting the input saves the combined draft; Revert restores the saved configuration. A small value type, `WeatherSettingsInput`, separates raw text from validated preferences.
- **Application settings:** display mode, fullscreen behavior and refresh interval have separate action handlers. An exact imported interval appears as a custom picker entry instead of rounding to a preset. Unrelated actions preserve it.
- **Workspace queries:** every command rejects failed, timed-out and truncated output. Malformed window records cause an explicit warning. The snapshot identifies unavailable detail queries; the controller preserves previously confirmed fields for those queries while displaying the warning. Successful empty results clear old data. Automatic fallback depends on source availability rather than a presentation string.
- **Workspace actions:** switching/focusing returns errors instead of discarding them. Failed actions remain visible in diagnostics, copied reports and the active-app tooltip until a successful action or configuration change. The CLI's documented no-focused-window result remains a valid empty-workspace state. [Upstream command documentation](https://nikitabobko.github.io/AeroSpace/commands#list-windows) and [implementation](https://github.com/nikitabobko/AeroSpace/blob/main/Sources/AppBundle/command/impl/ListWindowsCommand.swift) explain that distinction.
- **Shared controls:** themed button measurement and drawing use the same padding, symbol, subtitle and trailing-content reservations. Native bezel alignment insets are removed for custom drawing. Timer presets wrap to another row at their measured width, including six long presets. Native button keyboard and accessibility behavior is retained.
- **Diagnostics:** model, UI and navigation use one provider list. Timer, Keep Awake, Reminders and Keyboard now have rows. A widget with no general settings, such as Audio, offers arrangement navigation rather than implying that a settings page exists.
- **Developer docs:** architecture guidance describes query recovery and raw input handling; the widget guide points to actual feature model files rather than nonexistent `MiniAppModels.swift`.

## Remaining production work

Settings still share a broad controller, other field editors do not yet use a common editing-session abstraction, provider services use a singleton composition pattern, and panels still share feature-specific state. Explicit accessibility journeys, supported macOS/Intel/multi-monitor qualification and signed update installation/rollback also remain outstanding.

This pass addresses concrete failures without claiming the wider architecture or release qualification is complete. The next structural pass should extract configuration editing ownership and field validation, then separate feature panel state and inject the service graph.
