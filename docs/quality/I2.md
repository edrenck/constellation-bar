## Reproduced findings

Before implementation, a probe linked against I1 production objects confirmed that a saved disconnected-display layout contributed Keep Awake to the sampling list; 25 windows produced only nine overview cards or eight switcher rows; and a transient Reminders read failure changed an authorized state to unauthorized and discarded its tasks. The display observation established the scope calculation error, not a physical monitor-disconnect test.

Native regression tests also reproduced floating panels surviving both bar closure and hiding, plus coordinator deallocation. These lifecycle failures were fixed in the same pass.

## Behavior and organization

- **One display ownership model:** [DisplayScope](../../Sources/ConstellationBar/Core/Configuration/DisplayConfiguration.swift) resolves ordered connected display IDs, primary-only mode, enabled overrides and effective layouts. Rendering, sampling and diagnostics share it. Disconnected overrides and an unused shared layout no longer activate providers. Scope changes invalidate old samples and deactivate providers that lose their last target display. Temporary fullscreen hiding keeps provider ownership intact.
- **Complete window collections:** [WindowCollectionPanel](../../Sources/ConstellationBar/Shell/Workspaces/WindowCollectionPanel.swift) owns the bounded viewport, document geometry, native scrolling, collection count, focus reveal and key-view order. Overview/switcher features supply all cards/rows. A 25-window fixture reaches the last item by scrolling, keyboard focus and action routing; the grid reflows in a 220-point viewport. The switcher reveals its focused row after the initial clip-view layout settles.
- **Explicit UI teardown:** closing or hiding a bar dismisses its panels. [Overlay coordinator](../../Sources/ConstellationBar/Shell/Panels/OverlayCoordinator.swift) teardown closes floating windows, cancels pending work and removes the keyboard monitor. Tests exercise real bar controls, actual floating panels and coordinator lifetime.
- **Reminders state and effects separated:** [models/contracts](../../Sources/ConstellationBar/Widgets/Daily/RemindersModels.swift), [EventKit adapter](../../Sources/ConstellationBar/Widgets/Daily/AppleRemindersReader.swift) and [provider lifecycle/cache](../../Sources/ConstellationBar/Widgets/Daily/RemindersProvider.swift) have separate ownership. Authorization is checked independently of read success. Failures keep a marked saved snapshot for at most five minutes, retry every 15 seconds, and offer an immediate Retry action through the provider queue. Revocation, list changes and deactivation clear prior tasks. Never-fetched or expired results show unavailable. Displayed task totals distinguish the complete count from the first 100 rendered tasks.
- **Truthful Calendar action:** Open Calendar/Outlook describes the current application handoff. It does not imply navigation to the selected event; no undocumented event-link scheme was introduced.

These are focused ownership changes within the existing executable target. The broader settings-session extraction, shared-service composition and feature-panel state separation remain outstanding.

## Remaining work

The [blind assessment](reviews/I2.md) rated code quality **8.0**, usability **7.5** and UI **7.5**. It observed poor contrast in the collapsed workspace selector on light themes and called out missing explicit settings accessibility names, unclamped overlay sizes, obsolete canonical documentation and truncated window titles without tooltips. The lower UI rating records newly observed evidence; these independent subjective scores are not expected to rise at every checkpoint.

Configuration editing still combines draft state, save/Undo logic and page controls in one broad window controller. Feature panels share state through `MiniAppPanel`, and provider composition still relies on shared global services. Calendar selection remains outside JSON configuration and Undo. A direct accessibility audit, signed packaged installation/update recovery, and supported OS/Intel/physical-display qualification also remain outstanding. This checkpoint is not a declaration of production readiness.
